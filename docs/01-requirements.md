## 1. 产品一句话

**一个 Agent-first 的 bot IDE：用对话让 Agent 写代码，人在 IDE 里审查、运行、调试，产物是能在任何平台上线的 bot。**

不是低代码画布，不是插件市场；它是一个**面向 bot 的 IDE**，不是通用 IDE。核心资产是：

1. 一个能读写多文件项目、运行、看日志、自己修的 **Agent**；
2. 一个**可靠、低内存、跨平台**的 bot 运行时；
3. 一个**代码优先的 IDE**：编辑器、搜索、问题、Diff、运行、调试、日志；
4. 一套**可被 Agent 理解**的目录与契约。

## 2. 用户与场景

| 用户 | 特征 | 关键诉求 |
|---|---|---|
| 个人 bot 作者 | 会一点代码，不想搭脚手架 | 描述需求就能跑；出问题能看懂日志 |
| 小型团队/社群运营 | 要 7×24 稳定，偶尔改逻辑 | 不丢消息；后台运行；改完即生效 |
| Agent 本身 | 读目录、改文件、跑命令 | 路径可预测、错误可读、边界明确 |

### 2.1 核心用例

**UC-1 从零创建一个 bot**

1. 新建项目，选平台（OneBot 11 / Webhook）与模板。
2. 对 Agent 说“收到 hello 回复 world，其他消息记录到 kv”。
3. Agent 在 `src/main.ts` 与 `src/lib/` 写多文件代码，改 `hbot.json`；每次写入以 Diff 呈现，用户逐块接受。
4. 编译错误显示在问题面板；Agent 一轮内自动修复（最多 2 次）。
5. 在运行面板注入 mock 消息，看到回复与日志；确认后接真实平台。

**UC-2 用日志迭代**

1. 真实消息触发异常。
2. 用户在日志面板看到错误与源码位置。
3. 把错误发给 Agent；Agent 读代码、改、热重载。
4. 旧版本在修复前继续服务。

**UC-3 长期后台运行**

1. 桌面关窗后 bot 继续跑（可配置）。
2. 断线自动重连；未发送消息排队重试。
3. 崩溃后重启，恢复未处理消息。

**UC-4 多项目切换**

1. 每个项目独立源码、DB、日志、密钥引用。
2. 切换项目不丢当前编辑；后台 bot 按项目隔离。

**UC-5 安全地给权限**

1. 默认只读/工作区写；命令需审批。
2. 生成代码默认无网络；按域名开白名单。
3. 密钥进 OS keychain；日志脱敏。

## 4. 非功能需求

| 类别 | 要求 | 验证 |
|---|---|---|
| 内存 | 桌面整机 < 260 MB（private commit 求和）；核心 < 60 MB；每 bot < 6 MB | 进程采样，见 05 §4（已实测：核心 3.4 MB、整机 206 MB 中位） |
| 启动 | headless 核心可用 < 800 ms；桌面到 IPC 首次可用 < 1500 ms | 真机分段采样（headless 878 ms 未达标；桌面 1049 ms 中位，其中核心仅 33 ms，见 ADR-0002 §4.2 与 `scripts/startup-probe.ps1`） |
| 可靠性 | 不丢入站；同会话有序；重复只执行一次 | 注入/断网/杀进程测试 |
| 恢复 | 崩溃后重放未处理消息；outbox 继续 | 集成测试 |
| 安全 | 生成代码无 fs/net/process；命令默认审批；密钥不落日志 | 红队用例 |
| 跨平台 | Windows/macOS/Linux 桌面；Linux 无 GUI 后台 | CI 打包 + smoke |
| Agent 效率 | 目录可预测；契约单一；`check.sh` < 90s | 闸门 + 实测 |
| IDE 响应 | 按键 p95 < 16ms；打开 1MB 文件 < 150ms；全局搜索首屏 < 1s | 固定夹具基准 |
| IDE 内存 | 20 标签时 UI 进程 < 300MB | 进程采样 |
| 可维护 | 无循环依赖；无第二套循环/契约；any=0 | xtask + clippy |

## 5. MVP 范围

**包含**：FR-1 ~ FR-14、FR-18（SDK + OneBot + Webhook）、FR-19 ~ FR-22、FR-24；FR-23/FR-25/FR-26 做最简版。

**不包含**：FR-15 之后除上述之外的项；macOS 公证；自动更新下载安装；MCP；多平台适配器（飞书/钉钉/Telegram 等，MVP 后）。

**MVP 验收**：

- [ ] Agent 从空项目写出多文件“hello → world”，每个文件改动都有 Diff，可逐块接受/拒绝。
- [ ] 编辑器可打开/编辑/保存/搜索/跳转定义；关闭再开恢复标签与布局。
- [ ] 编译错误显示在问题面板；Agent 能根据诊断自动修复一轮。
- [ ] OneBot 测试账号：连发 100 条有序、断网 30s 不丢、重复投递只执行一次。
- [ ] 热重载失败时旧版本继续跑。
- [ ] 只读档拒绝写；命令无隔离时拒绝执行。
- [ ] 桌面空闲 RSS 与启动达标（实测数字写入 `docs/spikes/`）。
- [ ] Linux `hbot serve` 由 systemd 启停。

## 6. 约束与假设

- 单机、单用户；不做云同步。
- 平台以 OneBot 11 + 通用 Webhook 为主；其他平台按适配器扩展，不在核心写平台分支。
- 生成代码是多文件 TypeScript；只允许相对 import，不支持 npm 依赖。
- 用户机器可能没有 Node；产品不得要求安装。
- macOS 可能没有可用的命令沙箱；届时禁用命令工具并说明。
- LLM 由用户自带 API Key；默认不内置代理服务。

## 7. 成功指标（上线后 30 天）

| 指标 | 目标 |
|---|---|
| 新用户从安装到 bot 回复第一条消息 | 中位 < 10 分钟 |
| 崩溃/重启导致的消息丢失 | 0（可归因于平台的除外） |
| 同会话乱序投诉 | 0 |
| 桌面崩溃率 | < 0.5% 会话 |
| 平均空闲内存（private commit） | < 260 MB（实测中位 206 MB） |
| Agent 一次修复成功率（编译/测试通过） | > 70% |

## 8. 未决

1. 平台优先级：OneBot 11 之后先做 Webhook 还是飞书。
2. `onSchedule` 是否进 MVP（当前列 P1）。
3. 多文件模块加载器的实现路径（QuickJS 原生 loader vs 编译期打包）；用户可见都是多文件源码。
4. macOS 首发是否只出未签名包。
5. 是否提供旧项目 `flow.json` 的“参考导入”（当前明确不做）。
