# 06 IDE 设计（Agent-first Bot IDE）

- 状态：Draft（与 [ADR-0002](adr/0002-agent-in-rust.md)、[02 架构](02-architecture.md) 对齐）
- 日期：2026-11-16
- 一句话：**这是一个用 Agent 写 bot 的 IDE，不是“带编辑器的聊天框”。代码是唯一真源，Agent 是协作者，产物是能在任何平台上线的 bot。**

---

## 1. 产品形态与三条不变量

产品形态：本地桌面 IDE（Tauri + React + Monaco）+ 同一核心的 `hbot serve` 无头运行。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 菜单 / 命令面板 / 项目切换                        运行中：3 bots  ● │
├──────┬───────────────────────────────────────┬───────────────────────┤
│ 活动 │  编辑器（标签页 · 面包屑 · 分栏）      │  Agent                │
│ 栏   │  src/main.ts  src/lib/reply.ts  +      │  ┌─────────────────┐  │
│      │                                        │  │ 对话 / 计划      │  │
│ 资源 │  1  import { defineBot } from 'hbot'   │  │ 工具卡 / 审批    │  │
│ 搜索 │  2                                     │  └─────────────────┘  │
│ 运行 │  3  export default defineBot({         │  ┌─────────────────┐  │
│ 设置 │  4    async onMessage(ctx) {           │  │ 变更 Diff 审查   │  │
│      │  5      await ctx.reply('hi')          │  │ 文件 · 冲突提示  │  │
│      │  6    }                                │  └─────────────────┘  │
├──────┴───────────────────────────────────────┴───────────────────────┤
│ 问题 3 · 输出 · 日志 · 调试控制台                        行 5 列 12  │
└──────────────────────────────────────────────────────────────────────┘
```

三条不变量（违反任何一条就是设计错误）：

1. **代码是唯一真源。** 没有隐藏的 flow.json、没有“只存在数据库里的逻辑”。Agent 与人都改同一批文件。
2. **Agent 的每次写入必须是可审查的 Diff。** 不存在“Agent 直接改动、用户事后才发现”的路径；用户可逐块接受/拒绝。
3. **IDE 不拥有运行时真相。** 运行状态、队列深度、日志、调试暂停都来自核心事件；UI 不自己推断“应该还在跑”。

## 2. 布局与面板

| 区域 | 内容 | 默认 | 可关闭 |
|---|---|---|---|
| 活动栏 | 资源管理器 / 搜索 / 运行 / 设置 | 左，48px | 否 |
| 侧栏 | 文件树、搜索结果、运行目标、设置页 | 左，240–420px | 是 |
| 编辑区 | 标签页、面包屑、Monaco、分栏、Diff 编辑器 | 中，自适应 | 否 |
| Agent 栏 | 对话、计划、工具卡、审批、Diff 审查 | 右，320–560px | 是 |
| 底部面板 | 问题 / 输出 / 日志 / 调试控制台 | 下，160–400px | 是 |
| 状态栏 | 项目、分支（P1）、沙箱档、模型、队列、行列 | 底，24px | 否 |

**布局只有一个真源**：`apps/web/src/lib/layout.ts` 的 `resolveLayout()`。侧栏与 Agent 栏的宽度、折叠阈值、分隔条宽度都从它来；组件不得各自写死宽度。旧项目踩过的坑：两套布局档位、CSS Grid 与内联宽度叠加 —— 新项目不重复。

## 3. 编辑器能力

### 3.1 MVP（M1 必须可用）

- Monaco，TS/JS/JSON/Markdown；每个文件一个 model，关闭标签时 `dispose()`。
- 打开、保存、全部保存、另存为；脏标记；外部修改检测（watcher 事件 → 提示“磁盘已变更/重新加载/保留我的”）。
- 标签页：切换、关闭、关闭其他、重新打开；分栏（最多 2 列）；会话恢复。
- 导航：快速打开（文件名模糊搜索）、转到定义、查找引用、符号大纲、面包屑。
- 编辑：多光标、查找/替换（当前文件）、格式化、括号匹配、自动缩进、行号、当前行高亮。
- 诊断：Monaco TS 诊断（类型/语法）+ 运行时错误（source map 映射回文件:行）+ `hbot.json` schema 校验；问题面板可点击跳转。
- 保存前检查：语法错误不阻塞保存，但运行前必须编译通过；编译错误显示在问题面板与状态栏。

### 3.2 P1

- 行内编辑（`Cmd/Ctrl+K`）：选中代码 → 自然语言 → 生成 Diff → 接受/拒绝。
- 代码动作：`Fix diagnostic`、`Explain`、`Add log`、`Wrap in try/catch`。
- 重命名符号（Monaco TS 提供）；跨文件重命名走同一套 WorkspaceEdit。
- Peek definition / Peek references；调用层级（P2）。
- 代码折叠、缩略图、空白符、自动换行开关（按语言记忆）。
- 主题：浅色/深色/跟随系统；字体与字号可调。

### 3.3 明确不做

- 扩展市场、任意 VS Code 插件、npm 依赖安装。
- 远程开发 / SSH 工作区（P2 再评估）。
- 终端（MVP 不做；命令通过 Agent 的 `run_command` 与审批执行）。
- Git 图形界面（P1 可做最小“变更列表 + 提交”，不做分支图谱）。
- Vim 模式（Monaco 可开，P1 作为设置项，不自己实现）。

## 4. 项目与文件模型

### 4.1 多文件项目

```text
<project>/
  hbot.json            # 清单：name、entry、platform、permissions、limits
  tsconfig.json        # 由创建项目时生成，给 Monaco 用
  src/
    main.ts            # 入口（默认）
    handlers/          # 事件处理
    lib/               # 纯函数与工具
  vendor/              # 可选：项目内手写/粘贴的纯 JS 模块，无 npm
  hbot.d.ts            # 宿主 API 类型（核心生成，勿手改）
  .hbot/               # 运行数据、日志、编译缓存（gitignore）
    hbot.db
    logs/
    build/
```

**模块规则（硬）**：

1. 只允许**相对路径 import**（`./x`、`../lib/y`）。禁止裸包名（`import x from 'axios'`）——运行时不装 npm。
2. `vendor/` 下的 `.js`/`.mjs` 允许被相对导入；不得有 `package.json` 依赖解析。
3. 不支持 `require`、`import()` 动态导入、`eval`、`new Function`。
4. 循环 import 由模块系统按 ES 语义处理；不额外禁止，但 lint 警告。
5. 入口由 `hbot.json` 的 `entry` 指定，默认 `src/main.ts`；入口必须 `export default defineBot({...})`。
6. 每个文件独立 SWC 去类型 + source map；QuickJS 模块加载器按需解析依赖。
7. 类型检查只在 WebView 的 Monaco 里做；运行时不做类型检查。

### 4.2 文件操作

- 创建/重命名/删除/移动前检查路径：必须在项目根内、不能是 `.hbot/`。
- `hbot.d.ts` 是**核心生成物**：UI 置只读，Agent 工具层拒写（`workspace` 层不拦，否则生成器自己写不了）；被外部改坏时下次启动重新生成。
- 重命名文件时重写相对 import（Monaco 的 TS 服务给 edits；核心落盘前二次校验）。
- 删除文件进入“待确认”状态，不直接进回收站；项目内 `.hbot/trash/` 保留 7 天。
- 二进制/超大文件（>2MB）只读，不在 Monaco 打开，提示用外部工具。
- 所有写盘走核心的 `fs.write`（原子写：tmp → fsync → rename），UI 不直接写磁盘。

## 5. Agent 集成

### 5.1 对话与上下文

- Agent 栏是唯一对话入口；每个项目一个会话列表，会话可重命名/删除。
- 上下文 chip：`@file`、`@folder`、`@selection`、`@diagnostics`、`@logs`、`@platform-docs`；用户可见、可移除。
- 默认上下文：当前打开文件 + 选区 + 相关诊断 + 项目 `hbot.json` + `hbot.d.ts` 摘要；不自动灌整个仓库。
- 计划：需要多步时先出计划（可编辑、可跳过步骤），执行中逐步更新状态。
- 工具卡：每个工具调用一张卡（读/写/命令/运行/搜索），显示参数摘要、结果摘要、耗时、可展开。
- 审批：写项目外、执行命令、联网、危险操作必须弹审批；审批键 = `(工具, 规范化参数/路径, 沙箱档)`；“总是允许”只对**当前完整动作**生效。

### 5.2 写入与 Diff

- Agent 的写操作统一走 `workspace.applyEdit`：生成 `WorkspaceEdit`（文件、范围、替换文本），先算 Diff，再让用户逐块接受/拒绝。
- 用户未保存的缓冲区有改动时：Agent 编辑基于**磁盘版本**还是**缓冲区版本**必须显式选择；默认基于缓冲区（避免覆盖用户正在写的内容），并在 Diff 上标注“包含未保存修改”。
- 冲突：Agent 生成 Diff 后用户又改了同一范围 → 拒绝自动应用，提示重新生成或手工合并。
- 应用后：保存文件、触发编译、把编译/诊断结果回灌给 Agent（一轮内自动修复，最多 2 次）。
- 撤销：Agent 的一次应用 = 一个 undo 组，`Cmd/Ctrl+Z` 整组回退。

### 5.3 行内编辑与快捷动作

- `Cmd/Ctrl+K`：选区 + 指令 → Diff 预览 → 接受/拒绝。
- 问题面板每条诊断有 `Fix`（把诊断 + 文件范围发给 Agent）。
- 运行失败有 `Ask Agent to fix`（附错误、栈、最近日志）。
- 日志行有 `Explain this log`。

### 5.4 禁止

- Agent 不得在用户未确认时删除文件、改 `hbot.json` 权限、执行项目外写、执行命令。
- Agent 不得把密钥写进代码或日志；上下文里的密钥一律脱敏。
- Agent 不得“声称已运行”而没拿到运行结果；工具结果必须来自真实调用。

## 6. 运行与调试

### 6.1 运行

- 运行面板：选择 bot（一个项目可有多 bot 配置）、平台适配器、启动/停止、状态、队列深度、最近错误。
- Mock 事件：选择平台模板（群消息/私聊/按钮回调/定时），填字段，注入到当前 bot；用于不连真实平台的自测。
- 日志：底部面板流式显示，按级别过滤；点击栈帧跳到源码；日志环形缓冲 10,000 行，超出落盘。
- 运行结果：每条 mock 事件的输出（回复文本、API 调用、耗时）显示在“运行”页，可复制为测试用例。

### 6.2 调试（MVP：源码级插桩，不是 V8 Inspector）

为什么不用 V8 Inspector：QuickJS 没有可用的断点调试接口，换 `deno_core` 会把每个 bot 的内存从 MB 级推到几十 MB，违背“多 bot 常驻”的目标。

方案：**debug build = 插桩 build**。

```text
源码 --SWC strip--> AST --插桩--> 每个语句前插入 __hbot_trace(fileId, line, col, scopeSnapshot)
                                        │
QuickJS worker 执行到 __hbot_trace ──────┤
                                        ├─ 无断点：立即返回（开销极小）
                                        └─ 命中断点：阻塞 worker，发 debug.paused
                                                   UI 显示文件/行/局部变量
                                                   UI 发 resume/stepOver/stepInto/stepOut
```

- 断点：行断点、条件断点（表达式在宿主侧用受限求值器算，只允许比较/布尔/字面量）。
- 步进：`stepOver` 用插桩深度判断；`stepInto` 进入被调函数的下一个 trace；`stepOut` 回到上一层深度。
- 变量：插桩时按作用域收集**可 JSON 序列化**的局部变量；不序列化函数/循环引用/超大对象（显示 `<unserializable>`）。
- 调用栈：插桩维护逻辑栈（文件、函数名、行），不依赖引擎栈。
- 不支持（MVP 明确写进 UI）：`eval`/watch 任意表达式、原生 async 栈、DOM、性能剖析。
- 性能：debug build 允许 2–5× 变慢；release build 不含插桩。同一份源码，两种编译产物；UI 明确标注“调试模式”。
- 错误：release 错误用 source map 映射；debug 错误带逻辑栈。

### 6.3 测试与回放

- 每个项目可有 `tests/*.test.ts`（用宿主提供的 `test` API，不装测试框架）；运行面板可跑单条/全部。
- 回放：从 `inbound` 选一条历史事件，用当前代码重跑，输出与当时对比（Diff）；用于“改完有没有变好”。
- 录制：把一次 mock/真实会话保存为 fixture，供回归测试。

## 7. 搜索、诊断、重构

- 全局搜索：Rust 侧 `ignore` + `grep-searcher` 流式返回；支持正则、大小写、包含/排除 glob；结果按文件分组，点击跳转；替换前预览全部命中。
- 诊断来源：Monaco TS、`hbot.json` schema、编译错误、运行时错误、lint（Biome 规则子集，仅提示）。
- 重构：重命名符号、提取函数（P1）、移动文件并重写 import（P1）。
- 索引：文件树与符号索引在内存；项目 <5,000 文件不做持久化索引，启动时流式扫描。

## 8. 状态、命令与持久化

**一个命令入口**：UI 所有动作都是 `dispatch(command)`（与核心同一套 Command DTO，经 Tauri IPC 或 WS）。UI 内部快捷动作也走命令，不直接改多个 store。

Store 划分（Zustand，三个，不交叉写）：

| store | 拥有 | 不拥有 |
|---|---|---|
| `workspaceStore` | 项目、文件树、标签、脏状态、布局、搜索结果 | 运行状态、Agent 对话 |
| `agentStore` | 会话、消息、工具卡、审批、Diff、计划 | 文件内容（只读引用） |
| `runStore` | bot 状态、队列、日志、调试会话、回放 | 文件与布局 |

跨 store 只通过**事件**（`bot.status`、`diagnostics`、`agent.diff`）与**命令**协作；禁止一个 store 直接调另一个的 setter。旧项目 19 个 flow slice 互相编排的复杂度，不在新项目重演。

持久化：

- 会话恢复：打开的标签、光标位置、布局、侧栏状态 → 本地 `settings`（核心）或 IndexedDB；崩溃后恢复。
- 未保存缓冲区：IndexedDB journal，节流 500ms；下次启动提示恢复。
- 项目切换：先 `flush` 当前缓冲区与 Agent 进行中的写入，失败则阻塞切换并提示。

## 9. 性能预算（IDE 侧）

| 指标 | 预算 | 测量 |
|---|---|---|
| 按键到屏幕 | < 16ms（p95） | 输入延迟基准 |
| 打开 1MB 源码 | < 150ms | 冷/热各一次 |
| 20 个标签内存 | UI 进程 < 300MB | 任务管理器/进程采样 |
| 全局搜索首屏 | < 1s（10,000 文件，流式） | 固定夹具 |
| TS 诊断 | < 500ms（单文件保存后） | Monaco 回调计时 |
| 项目启动到可编辑 | < 1.5s | 冷启动 |
| 日志吞吐 | 10,000 行不卡 UI | 环形缓冲 + 批量渲染 |
| Diff 渲染 | 5,000 行 < 200ms | 虚拟化 |

超预算的处理顺序：虚拟化 → 减少重渲染 → Web Worker → 降级功能（不做“假装很快”）。

## 11. 可访问性与 i18n

- 键盘可达：所有面板、标签、Diff 操作可纯键盘完成；焦点环可见。
- 对比度：正文 ≥ 4.5:1；不只用颜色表达状态（运行/错误带图标与文字）。
- 屏幕阅读器：按钮有 `aria-label`；实时日志用 `aria-live="polite"`，错误用 `assertive`。
- i18n：UI 文案走 `t()`；中英两套；代码与日志不翻译。默认跟随系统，可设置。

## 12. 与旧项目的关系（只取教训，不搬代码）

**值得保留的做法**：

- Monaco 集成、TS 诊断、布局单一真源、面板懒加载（首屏只加载当前面板）。
- “问题 → 修复”的闭环、日志点击跳源码。
- 保存前校验、原子写、外部修改提示。

**明确不重复**：

- 19 个 flow slice 的跨 store 编排；一个动作改 4 个 store。
- 编辑器/画布双真源；图存在 JSON、逻辑存在另一处。
- 一个组件 600 行、一个文件 2,000 行的“功能堆叠”。
- 用 `any` 和空 catch 换速度；IDE 的状态机必须显式。

## 14. 未决

1. 多文件模块加载器用 QuickJS 原生 ES module loader，还是编译期打包成单文件？前者保留文件边界，后者实现简单；S1 实测后定。
