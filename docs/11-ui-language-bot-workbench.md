## 0. 证据与判据口径

### 0.1 证据等级（本文所有结论都带这一档）

| 标记 | 含义 |
|---|---|
| 实测 | 从构建产物 / 源码里量出来的数字（CSS 声明值、对比度计算、行数、常量值） |
| 读码 | 读源码得出的行为（契约 DTO、store、组件结构），没跑起来验证 |
| 推测 | 没有直接证据、按经验给的判断，落地前要复核 |

- Mino 侧：`mino/assets/index-PA8dFB3N.css`（297 958 B / 2 848 条规则）逐条读，取声明值 —— 实测。
- HBot 侧：`apps/web/src/styles/theme.css`、`apps/web/src/styles/app.css`（3 041 行 / 421 条规则）、`apps/web/src/lib/layout.ts`、`apps/web/src/generated/*.ts` —— 实测（声明值）/ 读码（行为）。
- 对比度：WCAG 2.x sRGB 相对亮度公式实算，附录 A 有全部数值，可复算。
- 未做：没有把两个界面跑起来做像素比对；视觉判断里的「观感」类结论都标了推测。

### 0.2 五条判据（后文每个建议都用 Qn 标注它为什么成立）

| 判据 | 内容 | 用在哪 |
|---|---|---|
| **Q1 频次** | 同一屏出现 >50 次的元素：装饰预算 ≤2px、无阴影、无动画、无图片 | 树行、日志行、表格行、页签 |
| **Q2 布局** | 任何改变布局尺寸的过渡都是 bug —— 编辑器与日志会 relayout，滚动位置会跳 | 侧栏/面板宽度、折叠 |
| **Q3 语义** | 颜色不能是唯一信号；每个状态必须有形状或文字冗余（`docs/06-ide.md` §11） | bot 状态、级别、能力三态 |
| **Q4 诚实** | 不能把「声明了」显示成「可用」，不能把「宿主没装配」显示成「已启用」（ADR-0005：存在不等于授权） | 能力面板、总览页 |
| **Q5 对比** | 正文 ≥4.5:1、大字 ≥3:1、部件边界 ≥3:1；**但主正文不超过 12:1** —— 超过会出现光晕/拖影，长时段阅读反而更累 | 全部文字令牌 |

Q5 的后半句是这次「低对比度」要求的正面表述：低对比 ≠ 整体压暗，而是**压缩明暗跨度**（最高压到 ~11、最低抬到 ≥4.5），同时把层级差异从「亮度差」转移到边框 / 字重 / 字号 / 位置。

## 1. ① 设计语言清单

### 1.1 结论先行（可沿用 / 必须改 / 不沿用）

**可直接沿用（4 项，Mino 与 HBot 做法一致，不要动）**

1. **面板标题语言**：11px / 600 / `letter-spacing:.06em` / 大写 / `--fg-muted`。Mino 的 `.nav-label`（12px/650/.1em）是同一套语法，HBot 这条更省空间，保留 HBot 版本。
2. **表格密度语言**：11px 字号、`padding:2px 8px 2px 0`、等宽数字、`border-bottom:1px var(--border)`。这已经是 IDE 密度，Mino 的表格也是同一路数。
3. **语义色一档一色**：ok / warn / danger 各一个色相，不做渐变、不做第二档。Mino 的 `--green/--amber/--red` 与 HBot 的 `--ok/--warn/--danger` 结构相同。
4. **树行 22px 密度**：`.tree__row{height:22px;font-size:12px;gap:4px}`。这是 IDE 的通行密度，Mino 的 42px 导航项不能搬（见 §4）。

**必须改（6 项，都是「现在不达标」而不是「不好看」）**

| # | 现状 | 问题（实测） | 改法 |
|---|---|---|---|
| 1 | `--fg:#d7dae0` on `--bg` | 12.69:1，超过 Q5 上限，长时段刺眼 | → 11.03:1（`#c9cdd4`） |
| 2 | `--fg-dim:#6b7280` | 3.68:1 —— **不达 AA**，却用在 `.panel-hint`、`.panel-empty`、`.welcome__note`、`.log__time`、`.jobs-panel__label` 这些要读的文字上 | → 5.19:1（`#858c96`） |
| 3 | `--bg` vs `--bg-panel` | 1.09:1，面板与画布几乎同色，分区靠记忆不靠视觉 | → 1.13:1（提亮 panel） |
| 4 | `--border` vs `--bg` | 1.33:1，边框几乎看不见 | → 1.43:1，`--border-strong` → 1.80:1 |
| 5 | `.button--primary{background:var(--accent);color:#fff}` | **白字 3.22:1，12px 正文不达 AA**；且 hover 色 `#6a9dff` 是写死的（不在令牌里） | accent 拆两档：文字档 5.45:1 / 实底档 4.74:1（白字） |
| 6 | 尺寸体系 | Mino 36px 按钮 / 32px chip / 10–18px 圆角；HBot 4px 圆角 / 24px 按钮 —— 两套并存会打架 | 定死一套：圆角 3/4/6/8，控件 20/24/28，见 §1.5 |

**明确不沿用（详见 §4）**：大卡片网格、封面图与 `presets/`、`padding:84px 54px`、侧栏径向光晕、`rise` 入场动画、Geist webfont、渐变 + glow 主按钮、插画空态、emoji 选择器。

**为什么 accent 必须拆两档（这条最有实操价值）**：现在 `.button--primary` 用 `--accent` 当底色 + 白字 = **3.22:1**，12px 文字不达 AA。想同时满足「实底按钮上白字 ≥4.5」和「accent 文字在 panel 上 ≥4.5」，一组色做不到 —— `#5b8def` 上白字只有 3.23，`#2f6fdc` 在 panel 上当文字只有 3.5 左右。所以拆成 `--accent`（文字/线条）与 `--accent-fill`（实底）。

**Mino 的赭红 `--accent:#d1481a` 不进深色主题**（实测：在 `#17191d` 上 3.90，在 panel 上 3.58，文字不可用）。它有一个更硬的问题：

> 在 IDE 里，暖橙/赭红**已经是 --warn 与 --danger 的语义区**。把交互色也放进去，「选中」和「警告」就只差饱和度 —— 这正是 Q3 禁止的那种「只靠颜色」。Mino 里没这个问题，因为策划界面一屏上通常没有红色。

所以 Mino 的暖色只保留在**两个位置**，都不与状态色相邻：
1. **项目身份**：总览页项目名左侧 2px 竖条、项目页签的小方块，用 `--accent-2:#e8734a`（实测 on bg 5.85，可当文字/图形）。
2. **文档与空态图标**：单色 20px 线性图标用它，不填色块。

**中性灰的冷暖**：Mino 的 `--bg:#f7f6f2` 是暖灰，HBot 现用的 `#16181c` 是冷灰。**建议保持冷灰**（理由不是审美）：Monaco 的语法高亮里暖色 token 很多（字符串黄绿、数字橙、常量紫），底色一暖，这些 token 的对比会一起下降，等于用主题去抵消高亮。暖只在上面说的两处点缀。

### 1.3 字体层级

字体族**不变**（`--font-ui` 系统字体栈 / `--font-mono` JetBrains Mono→Cascadia→Consolas）。不引入 Geist Variable 或任何 webfont：

> 实测：`apps/web` 首屏预算被钉在 258 kB / gzip 81 kB（AGENTS.md §6），Monaco 已经是 lazy chunk。一个中英混排 webfont 子集 ≥40 kB，换来的「品牌感」在每天 8 小时的界面里不可见，而 `--font-ui` 里已经有 `Microsoft YaHei` 覆盖中文（Q1：字体是全局最高频元素，任何全局换字体都要按性能预算审）。

**七档字号（新增为令牌，现在散在 421 条规则里）**：

| 令牌 | 值 | 行高 | 字重 | 颜色 | 用在哪 |
|---|---|---|---|---|---|
| `--fs-2xs` | 10px | 1.3 | 500 | `--fg-dim` | 表格列头、`.jobs-panel__label`、状态栏次要项 |
| `--fs-xs` | 11px | 1.35 | 600 | `--fg-muted` | 面板标题（大写 + .06em）、页签、组头 |
| `--fs-sm` | 12px | 1.4 | 400 | `--fg` / `--fg-muted` | 树行、列表行、按钮、表格单元格、日志 |
| `--fs-base` | 13px | 1.5 | 400 | `--fg` | 面板正文、表单、对话框正文、编辑器（由 Monaco 自管） |
| `--fs-md` | 14px | 1.4 | 600 | `--fg` | 对话框标题、卡片标题 |
| `--fs-lg` | 16px | 1.35 | 600 | `--fg` | 页面主标题（总览/bot 详情身份条） |
| `--fs-xl` | 20px | 1.3 | 600 | `--fg` | 只用一次：总览页项目名（Mino 的 `25px/700` 标题输入框不进 IDE） |

**层级靠什么区分**（重要，决定改完之后「有没有层次感」）：

- 60% 的层次来自**位置与留白**（面板头 vs 内容、缩进 12px/层），不是字号。
- 30% 来自**颜色档**（`--fg` → `--fg-muted` → `--fg-dim`，三档实测 11.0 / 6.7 / 5.2）。
- 10% 才来自字号（10–16px 只跨 1.6 倍，再大就变营销页）。
- 字重只用 400 / 500 / 600 三档。Mino 的 650 / 700 在 13px 系统字体上会糊（Windows 下 `Microsoft YaHei` 无 650 字重，会伪合成）。

### 1.4 间距与密度

**4px 基准**，只用 8 个数：`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24`（令牌 `--sp-1..--sp-8`）。Mino 用到的 18 / 54 / 64 / 84 一律不进 IDE。

**行高表（这是密度的真正来源，比 padding 重要）**：

| 元素 | 高 | 依据 |
|---|---|---|
| 树行 `.tree__row` | 22px | 现状，沿用（一屏 ≥20 行） |
| 实体行（bot / 会话 / 作业列表） | 28px | 一行里有 ≥2 个可点区域，22px 会点错 |
| 表格行 | 20px | 现状 2px 上下 padding + 11px 字 |
| 日志行 | 20px | 现状 `padding:1px 0` + 12px 字，改后仍 20px |
| 分组头 / 段标题 | 24px | 11px 大写 + 上下 6px |
| 面板头 `.panel-header` | 32px | 现状 `min-height:32px`，沿用 |
| 页签 `.tab` | 34px | 现状，沿用 |
| 页头（身份条） | 56px | 16px 标题 + 12px 副行 + 上下 12px |
| 状态栏 | 24px | 现状，不可关 |

**内容边距**：面板内 12px（现状）；页面内 16px；总览页外围 24px（Mino 是 54px，见 §4）。

**密度验收判据**（1080p / 100% 缩放，侧栏 280 + Agent 380 + 活动栏 48）：

- 编辑器可见代码 ≥30 行（底部面板默认 220px 时）；
- 侧栏可见树行 ≥20；
- 底部日志可见 ≥8 行；
- 全屏无水平滚动条。

四条都满足才算「密度对了」；只满足「好看」不算。

### 1.5 圆角 / 阴影 / 动效

**圆角四档**（现状各组件自己写，有的 3 有的 4 有的 6）：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--r-xs` | 3px | kbd、标签、`.tab__dot` 类小元件 |
| `--r-sm` | 4px | 按钮、输入框、树行选中、日志级别块 |
| `--r-md` | 6px | 卡片、弹层内的分组、代码块 |
| `--r-lg` | 8px | 对话框、命令面板（最大档，不再往上） |

> 判据：圆角 >8px 在 22–28px 行高里会吃掉 4–6px 有效宽度，并让相邻的两行「看起来像按钮」。Mino 的 10/14/18px 是为 ≥36px 的控件和卡片准备的，尺寸体系不同（§4 第 3 条）。

**阴影只留一档**：

```css
/* 浮层专用：深色界面里「浮起」靠描边 + 亮度，不靠阴影扩散。 */
--shadow-pop: 0 8px 24px rgb(0 0 0 / 45%), 0 0 0 1px var(--border-strong);
```

- 卡片、行、面板：**不用阴影**，用 `1px --border`。
- Mino 的 `--hi: inset 0 1px 0 #fff9`（顶部 1px 高光）在深色下等于给每个卡片加一条亮线，密排时变噪点 —— 不沿用。
- Mino 的 `--shadow-lg: 0 32px 72px` 是亮色纸面的悬浮语言，深色下几乎不可见，只剩性能开销。

**动效**：

| 场景 | 时长 | 说明 |
|---|---|---|
| hover 换底色 | 80ms ease-out | 现状多数是 0，可保留 0；只给需要强调的行加 |
| 页签 / 分段切换 | 120ms | 只做内容淡入，不做位移 |
| 布局尺寸变化（侧栏/面板/Agent 宽度、折叠） | **0ms（禁止过渡）** | Q2：Monaco 与滚动容器会 relayout，420ms 的过渡等于 420ms 的抖动 |
| 弹层出现 | 0ms 或 100ms opacity | 键盘驱动的界面，等动画就是等 |
| 入场 / `rise` / `translateY(-1px)` / 图片 `scale` | **禁止** | Q1 |
| 循环动画（Mino 空态图标 5s） | **禁止** | 永久占合成层；且违反 `prefers-reduced-motion` 的最佳实践 |

全局兜底（现在只有个别组件处理）：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition-duration: 0ms !important; animation-duration: 0ms !important; }
}
```

### 1.6 容器三形态（行 / 段 / 卡）

这是从「游戏策划」迁到「IDE」最关键的一条结构规则：Mino 只有「卡片」一种容器，IDE 需要三种，且**优先级依次下降**。

| 形态 | 尺寸 | 结构 | 用在哪 | 判据 |
|---|---|---|---|---|
| **行** `.row` | 高 22/28px，全宽 | 单行 flex，hover 换底色，左内边距随层级 +12px | 树、bot 列表、会话列表、作业表格行、日志 | 一屏 >50 个（Q1）→ 零装饰 |
| **段** `.section` | 由 `.panel-header`(32px) + 内容组成 | 只有上下 1px 分隔线，无边框无底色 | 侧栏分区、详情页分段、设置页分组 | 段是「语义块」，不是「卡片」；不给它圆角和底色，否则一屏会浮起十几张卡 |
| **卡** `.card` | 内边距 12px，`1px --border`，`--r-md`，**无阴影** | 头（14px/600）+ 体 + 可选脚 | **只有**总览页右列、能力面板摘要、对话框内部 | 卡片 > 8 张就要考虑改成行或表 |

卡片的两条硬约束（防止 Mino 的卡片文化回流）：

1. **hover 只换边框色**（`--border` → `--border-strong`），不做 `translateY`、不做 `scale`、不做阴影加深。理由：12px 文字在移动时走亚像素重绘，会显得糊；且「会动」会被误读成「这是可拖拽的」。
2. **卡片内不放大图**。Mino 的 `.card-img{aspect-ratio:16/10}` 在 IDE 里没有对应物（见 §2 的「头像/封面」）。

列表（行形态）的两条细则：

- `:focus-visible` 用 `outline: 2px solid var(--focus); outline-offset: 1px`（**不是** 现状的 `-1px`）：密排列表里 `-1px` 会把 2px 环压在 1px 边框上，看起来像元素自身高亮，键盘用户分不清焦点在哪一行。
- 选中态与焦点态必须能同时看见：选中 = `--bg-active` 底色，焦点 = 外扩 2px 环，两者不互相覆盖。

### 1.7 空状态与错误态

**空状态分两档**（现在只有一个 `.panel-empty`，被用在了两种完全不同的场景）：

| 档 | 类 | 尺寸 | 内容 | 判据 |
|---|---|---|---|---|
| 行内空 | `.panel-empty`（沿用） | `padding:12px`，12px 字，`--fg-muted` | 一句事实（「没有可显示的文件。检查是否已打开项目。」） | 面板内、表格内、树内 —— 空间小，用户已经知道自己在哪 |
| 区域空 | `.empty-state`（新增） | 垂直居中，上下 24px，最大宽 380px | 20px 单色图标 + 13px/600 标题 + 12px `--fg-muted` 说明 + 1–2 个 24px 按钮 | 整页/整面板没有内容，且用户不知道下一步 |

`.empty-state` 的四条规矩：

1. **必须是「下一步做什么」**，不是「什么都没有」。例：能力面板空 → 「还没有可显示的作业　[看运行日志] [注入一条消息]」。
2. 图标 20px、单色、线性；**不用插画、不用 60px 圆角块、不用循环动画**（Mino 的 `.empty-icon{60×60;border-radius:18px;5s 循环}` 是网页语言，Q1 直接否掉）。
3. 不使用「鼓励式」文案（Mino 的「开始你的第一段冒险吧 ✨」）。IDE 的空态语气 = 状态栏：陈述 + 动作。
4. 空态也要有 `role="status"`（加载中）或普通静态文本（真空），别让屏幕阅读器读到两次。

**错误态分三档**（现有实现已基本正确，只补两条）：

| 档 | 位置 | 现状 | 改法 |
|---|---|---|---|
| 行内 | `.inline-error`（6px 8px，红底 12%） | 已有 | 加左侧 `2px solid var(--danger)` 竖条（Q3：不只靠底色） |
| 区域 | `ErrorBoundary` | 已有 | 文案要写「哪个区域挂了 + 怎么恢复（重新加载 / 打开日志）」，不要只写堆栈 |
| 全局 | 状态栏 `role="alert"` | 已有 | 保留。**不要用居中 toast**（Mino 的浮层语言）：toast 会盖住编辑区，且用户正在看日志时恰恰看不到它 |

### 1.8 可访问性硬指标（含 3 个现存的真实缺陷）

**目标线**（对齐 `docs/06-ide.md` §11，并把数值定死）：

| 项 | 指标 |
|---|---|
| 正文（≤16px） | ≥4.5:1，且 ≤12:1（上限，Q5） |

```
│ 启停按钮 │                                     │ 设备状态 24px│
│          ├─────────────────────────────────────┤              │
│          │ 跟随输出 ●开        [跳到最新 (3)]   24px│          │
└──────────┴────────────────────────────────────┴──────────────┘
  240px 固定        minmax(0,1fr)                  280px 固定
```

**尺寸关系（为什么左右固定、中间自适应）**：左右是索引（列表/摘要），宽度需求确定；中间是内容（日志），必须吃掉剩余宽度，否则长行折行会让行高从 20px 变成 40px，一屏少一半信息。列间分隔用 1px `--border`，不用 `gap`（gap 会露出底色，在深色里像两条深沟）。

**入口冲突要显式决策**：活动栏 ▶ 现在是「打开日志页签」。若新增「运行页」，建议 ▶ 打开运行页、底部日志页签保留（快捷键不变）。**这是交互变更，需要 lead 拍板**，本文只标注冲突，不替代决策。

### 4.2 替代方案的统一原则（写新样式时按这三条自检）

1. **装饰预算**：一个元素如果一屏出现 >50 次（Q1），它只允许有 1px 边框、纯色底、无阴影、无动画。
2. **动效预算**：只允许「不改变布局尺寸」的过渡（颜色/透明度）；任何改变尺寸的过渡都要先证明它不会触发编辑器 relayout（Q2）。
3. **意义预算**：一个颜色只能有一个含义，一个形状只能有一个含义。新增颜色前先问「它和现有 8 个语义色里的哪一个会混」。
